# SSH-доступ к серверам

## Быстрый старт

```bash
./scripts/bssh prod:web-01
```

`prod:web-01` = `<окружение>:<имя сервера>`. Окружение можно не писать, если
оно одно: `BSSH_ENV=prod ./scripts/bssh web-01`.

Под капотом Boundary получает из Vault SSH-сертификат на вашу сессию,
подписанный доверенным CA, — личные ключи не нужны.

## Чистый CLI (без обёртки)

```bash
boundary connect ssh \
  -target-name web-01 \
  -target-scope-name prod-servers \
  -- -A
```

Флаги после `--` уходят обычному ssh.

## Проброс портов

```bash
./scripts/bssh prod:web-01 -- -L 5432:127.0.0.1:5432 -N
# теперь локально: psql -h 127.0.0.1 -p 5432 ...
```

## Копирование файлов

scp через Boundary напрямую не работает — используйте поток через ssh:

```bash
# с сервера на локальную машину
./scripts/bssh prod:web-01 -- tar czf - /etc/app | tar xzf - -C ./backup/

# с локальной машины на сервер
tar czf - ./dist | ./scripts/bssh prod:web-01 -- tar xzf - -C /opt/app/
```

## Частые вопросы

**Под каким пользователем я попадаю на сервер?**
Под технической учёткой (обычно `ubuntu`) — её выдаёт Boundary. Кто именно вы
— фиксируется в аудите сессии Boundary, а не в имени пользователя.

**«У вас нет прав» / таргет не в списке.**
Вы не в нужной группе Keycloak. Напишите администратору, какой сервер и зачем
нужен — вам добавят в `boundary-<env>-server-access` или в точечную группу.

**Подключение зависает / timeout.**
Проверьте VPN/сеть до контроллера и воркера (порт 9202), либо проблема на
стороне воркера в той сети — сообщите администратору.

**Сессия оборвалась.**
У сессий есть лимит простоя (по умолчанию 30 минут без трафика) и общий
максимум 8 часов. Просто подключитесь заново — это новая сессия.

**Аудит.** Факт подключения (вы → сервер, время, объёмы) пишется в аудит
Boundary. Сами команды Boundary не записывает — команды видны в логах
сервера (auditd/sudo).
